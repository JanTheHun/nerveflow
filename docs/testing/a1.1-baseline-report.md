## 2. Canonical Failure Taxonomy  *(closes #43)*

### Category definitions

| Code | Name | Decision rule |
|---|---|---|
| **CAT-ENV** | External service unavailable | Test times out or self-skips because a required backing service (database, broker) is not running in the CI environment |
| **CAT-ARTIFACT** | Missing build artifact | Test cannot import or execute a file that must be produced by a separate build step not triggered by `npm ci` |
| **CAT-FIXTURE** | Missing fixture / workspace setup | Test creates temporary state in a hardcoded path that does not exist on a clean clone |

## 3. Skip / Quarantine Policy  *(closes #44)*

### Allowed skip patterns

These are the **only** permitted skip / quarantine forms in CI-critical suites.
Any other skip form must be approved by adding an entry here before merging.

| Pattern | Condition | Scope |
|---|---|---|
| `t.skip('PG unavailable')` in `memory_provider.test.js` | Inline skip when `PGVECTOR_*` env vars are absent | Permanent environment exclusion; removed when PG service is added to CI matrix |
| Quarantine via `{ skip: true }` in polling fixture data | Test-data-driven skip in `polling_ingress_connector.test.js` | Functional fixture skip; not a CI bypass |

### Disallowed skip patterns

The following forms are **not** permitted without a tracking issue and expiry date:

- Commenting out test cases
- `process.env.CI && t.skip(...)` without a linked issue
- Silently catching expected failures inside a test body
- Top-level `t.skip` on a CAT-PRODUCT failure (regressions must be fixed, not hidden)
